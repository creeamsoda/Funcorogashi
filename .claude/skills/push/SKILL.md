# push

ローカルのコミットをリモートへ push するためのスキル。

push は外部に変更を公開する操作なので、状態を確認したうえで安全に行う。ユーザーの意図しない履歴の上書きや、意図しないブランチへの push を避ける。

## 手順

1. **現在の状態を確認する**
   ```bash
   git status -sb
   ```
   - 現在のブランチ名、リモート追跡ブランチ、ahead/behind の状況を把握する。
   - まだコミットしていない変更があっても push 対象はコミット済みのものだけ。未コミットの変更が残っていることはユーザーに伝える。

2. **push すべきコミットがあるか確認する**
   - ahead が 0（push するものがない）なら、その旨を伝えて終了する。
   - behind がある（リモートが進んでいる）場合は、force push せず、まず `git pull --rebase` などで統合が必要かもしれない旨をユーザーに確認する。

3. **push する**
   - 上流ブランチが未設定なら設定しながら push する。
   ```bash
   git push -u origin <現在のブランチ>
   ```
   - 既に上流が設定済みなら単に `git push`。

4. **結果を報告する**
   - push したブランチと、リモートの状態（新しいPRを作れるか等、出力にヒントがあれば）をユーザーに伝える。

## やってはいけないこと

- ユーザーが明示的に依頼しない限り `git push --force` / `--force-with-lease` を使うこと。履歴の上書きは破壊的なので、必要な場合も必ず理由を説明して確認を取る。
- `git push` に無関係なブランチやタグをまとめて送ること（`git push --all` / `--tags` は依頼があったときだけ）。
- behind の状態を無視して強制的に上書きすること。
